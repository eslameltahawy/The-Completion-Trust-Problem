# Senior scenario — a partner says the credential was wrong

Do not start by blaming the trust model. Separate three explanations.

**The trust model is flawed** only if the record is accurate, the partner understood the promise, and that promise still fails the decision they need. Example: Verified certificates, read correctly, do not help partners tell competency from completion.

**The data is wrong or incomplete** if the ID points at the wrong person, the wrong course version, a historical import with a missing date, or a status that does not match the review record. Example: a version 1 completion is described as if it covered version 2.

**The partner expected something else** if they believed Verified meant "ready to hire" or that a Course Completion record was a competency credential. The certificate does not promise employment or future performance.

First checks, in order:

1. Open the ID on the partner page and record the status, course version, method, and the sentence about what it does not prove.
2. Compare that screen with the words the partner says they relied on.
3. In the reviewer record, confirm the decision, the reason, and that no second certificate was issued.
4. If it is a Historical Certificate, confirm the original date and version were preserved.

Corrective action follows the check. Fix the record if the data is wrong. Change the page wording if partners misread a true record. Change the assessment or the issuance rule only if accurate, understood certificates still do not support the decision. Do not auto-issue certificates to make a complaint go away.
